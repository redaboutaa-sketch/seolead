# Phase 2 — implementation notes

Design decisions and their reasoning. The narrative report is
`/opt/seolead/PHASE2_IMPLEMENTATION_REPORT.md`; this is the reference.

## Stack

Python 3.12 · FastAPI · Pydantic v2 · SQLAlchemy 2.x (async) · Alembic · asyncpg ·
httpx · PyYAML · pytest. Docker Compose, two services.

Not used, per the mission's "keep it operationally simple": Redis, Celery, extra
databases, agent frameworks. The pipeline runs inline. One operator running one
job does not need a broker, and a broker would need monitoring, a dead-letter
policy and a worker — three things that carry no weight in Phase 2.

## Database

Owner Decision 3: a dedicated database inside the existing engine, no new
container.

```
engine    platform_postgres (PostgreSQL 16.14, pgvector available)
database  seolead          owner seolead_app, PUBLIC CONNECT revoked
role      seolead_app      LOGIN, NOSUPERUSER, NOCREATEDB, NOCREATEROLE,
                           NOREPLICATION, NOBYPASSRLS
```

`seolead_api` reaches it by joining `techformanord_backend`, the network
`platform_postgres` is on. Joining is additive — no other container and no network
definition is modified. The alternative was a host port, and `platform_postgres`
binds `127.0.0.1` only.

Verified by `scripts/verify_db_privileges.sh` against the live catalogue:
`seolead_app` holds **zero** SELECT/INSERT/UPDATE/DELETE privileges on every table
in `acquisition_platform`, and can create and write tables only in `seolead`.

**Residual, documented:** `acquisition_platform` still allows `PUBLIC` to CONNECT —
a PostgreSQL default this project did not change, because changing it modifies
another team's production database. `seolead_app` can therefore open a connection
there and read nothing. Closing that is the platform owner's call.

Migration `0001_initial` is hand-written rather than autogenerated so the
constraints carry their reasoning.

|---|---|---|

| `research_source` | one item, **or** one source-level outcome | `ck_research_source_state` — the ten upstream states |
| `research_evidence` | a claim | `ck_research_evidence_observability` |
| `research_package` | sealed artefact (JSONB) | |
| `content_brief` | | `ck_brief_type`, `ck_brief_intent` |
| `content_draft` | output + usage; no hidden reasoning | |
| `qa_review` | one row per QA type | `ck_qa_status`, `ck_qa_type` |
| `approval` | human decision | `uq_approval_draft` — one history per draft |

Two shapes worth calling out.

**`research_source` rows exist for sources that produced nothing.** A rate-limited
source leaves a row with `status='rate-limited'`, no URL, and
`source_metadata.item_count = 0`. Without it, "could not look" and "looked and
found nothing" would be indistinguishable in the database.

**`approval` is a separate table, not a column on `content_draft`.** A nullable
`approved` boolean would have put "QA passed, so set approved" one line away.

## Providers

### ResearchProvider

`Last30DaysProvider` maps the wire format into `ResearchProviderResult`. Nothing
downstream sees a Last30Days shape; provider extras live namespaced in
`provider_metadata`.

The normalizer honours two upstream rules: unknown fields are omitted rather than
nulled (so nothing indexes — everything uses `.get()`), and only `no-results`
counts as a clean empty. An unrecognised state becomes `schema-drift`, which is
explicitly *not* clean-empty.

`_observability_for` maps freshness onto knowledge:
`contradicted`/`unsupported` → UNKNOWN; `stale` → ESTIMATED; undated → ESTIMATED;
`current` + dated → OBSERVED.

### LLMProvider

Capability-routed, usage-accounted. `NullLLMProvider` refuses rather than
fabricating. `HermesGatewayProvider` is a documented seam, not an implementation.

## Content types

Selectable in Phase 2: `ARTICLE`, `GUIDE`, `COMPARISON`, `LANDING_PAGE`. The enum
declares the rest; `selectable_content_types()` filters them out, so a profile
naming `SIMULATOR` still cannot produce one before its QA rules exist.

Selection follows intent, and `ARTICLE` is the residual rather than the default:
comparison query → COMPARISON, commercial → LANDING_PAGE, informational → GUIDE.
`LOCAL_PAGE` is deliberately unreachable — a local page needs locally-specific
verified facts and nothing enforces that yet.

## QA

Deterministic layer (blocking): presence of title/meta/body, body length, heading
structure, placeholder leakage, vertical forbidden phrases, **numeric claims absent
from evidence**, quantified restricted topics, required-facts usage, source
traceability, keyword-stuffing density, duplicate title, CTA presence.

Advisory layer (never blocking): intent alignment, usefulness, repetition, CTA fit.
Stored as a separate `QAReview` with `blocking` forced false on every finding. A
model asked "is this accurate?" answers confidently either way; treating that as
proof would be the failure this pipeline exists to prevent.

The numeric check compares digit-only forms, so `6 000`, `6.000` and `6,000` are
one quantity across fr-BE, nl-BE and en. Years (1900–2100) and numbers already in
the query are excluded as noise.

## Failure codes

`LAST30DAYS_UNAVAILABLE` · `LAST30DAYS_TIMEOUT` · `LAST30DAYS_CONTRACT_ERROR` ·
`RESEARCH_PARTIAL` · `RESEARCH_FAILED` · `LLM_NOT_CONFIGURED` · `LLM_TIMEOUT` ·
`LLM_PROVIDER_ERROR` · `CONTENT_GENERATION_FAILED` · `QA_FAILED` ·
`DATABASE_ERROR` · `INVALID_VERTICAL` · `INVALID_REQUEST`

Persisted on the row that failed. Detail bounded to 500 characters; provider errors
can carry unbounded external text.

## Observability

JSON logs with `correlation_id`, `vertical`, `keyword_id`, `research_run_id`,
`provider`, `duration_ms`, `status`, `error_code`, `draft_id`.

Every record passes a redactor covering `key=value`, `"key": "value"` and bare
`sk-`/`ghp_` tokens. The JSON-quoted form was added after a test showed the first
pattern missed `"secret": "..."` — the shape this application actually logs.

`/health` (liveness) and `/ready` (database + runner). A missing LLM key is
reported as a capability, not a fault.

## Security

- `.env` git-ignored, mode 600, generated password never printed.
- `.env.example` placeholders only; a test asserts nothing key-shaped is in it.
- Internal API behind `X-Internal-Key` with `hmac.compare_digest`, **failing closed**
  with 503 when unset.
- No public route, no Traefik labels, loopback-only host binding.
- Both containers: non-root, `read_only`, `cap_drop: ALL`, `no-new-privileges`,
  tmpfs `/tmp` `noexec,nosuid`, explicit CPU and memory limits.
- No Docker socket anywhere.
- Research runner publishes no port.
